# CareConnect Mobile architecture

React Native CLI Android app for CAREGIVER with strict TypeScript. The user requested Flutter replacement on 01/11/2026, then explicitly replaced the Expo approach with React Native CLI and limited the target to Android. Earlier Expo/Flutter design and progress documents are historical; this runtime decision supersedes their platform setup.

## Runtime boundaries

App.tsx mounts shared providers; src/app/navigation.tsx composes auth guard, four tabs (Today, Assigned visits, Work schedule, Profile) and detail/form stacks. Work schedule owns three sections: Day agenda, Register for shifts and Time off. The separate Work shifts tab and list stack route have been removed; WorkShift remains a registration detail/form route and ProviderSchedule remains the linked availability/cancellation route. Requests, retained deposits, certificates and signed-in devices are secondary destinations. Completed history remains within Assigned visits and a compatibility stack route. Visit filters use a focused modal; drafts are committed together on Apply. src/core contains HTTP/session, boundary parsers, memory resources/mutation hooks, bilingual copy fragments, theme/shared controls and foreground device access. Core never imports features. Feature-owned models/repositories/screens now include booking-requests, earnings and availability; the profile schedule module only reexports compatibility types. BE/FE code is never imported or executed by the app.

All business traffic uses the gateway /api/v1. ApiClient unwraps code=200/result; Page models retain server totals and pagination. Unknown JSON is parsed into typed models at boundaries. Domain text stays as provided. No API payload logging, persisted patient cache, offline mutation queue or patient database. Cache-Control:no-store is sent. Report images open as HTTPS links rather than disk-cached native previews. The native documents adapter uses open mode with no local copies or long-term file access grants.

## Session

Unified /auth/login and /auth/refresh with X-Client-Type:mobile supersede deprecated /auth/mobile aliases and web cookie/CSRF transport. Refresh tokens are in namespaced Android Keystore-backed Keychain storage, access tokens only in memory. GET /users/me checks ACTIVE and CAREGIVER. Backend authorizes every actual request. Retired Expo SecureStore entries are not imported; first CLI launch requires sign-in.

Storage writes are serialized. Session epochs reject responses from an earlier account/logout. Concurrent 401 requests share one rotation, retrying authentication failure once. Timeouts/5xx on mutations are not automatically retried. Transient restore failure retains the secure refresh token and shows retry; invalid credentials/role clear the session. Logout removes protected UI, forms, memory data and polling even if server revocation fails; revocation uncertainty is surfaced.

## Domain contracts

BookingOccurrence is an assigned visit. CareSession is actual care. Provider Schedule is assigned work availability, never simulated visit progress. Detail snapshots/services may be absent from list DTOs or hidden by scope. No secondary patient API bypasses snapshot visibility. Masked phones are not callable.

The work-shifts feature owns caregiver registration and supplies content embedded in Work schedule → Register. It shows Open, Pending, Approved and History subviews with server-backed date/type/vacancy filters and pagination. Pending/Approved use the current GET /work-shifts/registrations/me `status` parameter; History is the complete registration audit, including active records. Overview counts come from server totalElements on size=1 queries for OPEN shifts and PENDING/APPROVED registrations, never from visible-page sums or fabricated zeroes while loading. Work dates/times and registration deadlines are shown in Vietnam time. Detail reads the profile and scans all registration pages to detect an active PENDING/APPROVED registration. POST /work-shifts/{id}/registrations sends caregiverNote only (max2000); success remains PENDING until BE approval. Confirmed DELETE /work-shifts/registrations/{id}?version=... is available only for PENDING. APPROVED registrations offer a withdrawal entry to the linked availability schedule: that screen reads all necessary pages for the actual schedule/version and performs its own confirmed cancellation; it never uses registration DELETE for approved records. Embedded registration summaries preserve effective shift status, cancellation reasons and linked-schedule metadata when a shift is no longer readable. Readiness includes the center status; BE is authoritative for overlap/time-off, start/deadline/capacity and all writes.

Historical deviation (01/11/2026): non-null date filters caused PostgreSQL42P18/HTTP503, so the old board scanned all OPEN pages and filtered locally. Current BE commit eec3231 (05/11/2026) adds typed nullable predicates and effective lifecycle filtering. This update retires that workaround and uses the current server filter/page contract. The fix is source-verified; no live BE mutation or database migration is part of this update.

Visit statuses follow BookingService booking spec v1.0 (2026-11-02): a caregiver sees SCHEDULED, ACKNOWLEDGED, IN_PROGRESS, COMPLETED, CANCELLED, CAREGIVER_MISSED (formerly MISSED) and CUSTOMER_NO_SHOW; RESERVED, PENDING_ASSIGNMENT and EXPIRED exist before the customer pays and only have labels.

Acknowledgement posts /booking-occurrences/{id}/acknowledge. Starting posts /care-sessions and navigates using the returned sessionId. Session service uses configured startWindow/missedGrace (30 minutes each by default); late boundary and endAt are exclusive. Only IN_PROGRESS permits task/note edits. DONE counts as completed, SKIPPED requires a reason and is counted separately. Ending has confirmation; backend moves the occurrence to COMPLETED.

Customer booking requests are separate from occurrence acknowledgment. GET /bookings/caregiver-requests paginates privacy-limited previews. Accept posts /bookings/{id}/caregiver-accept without an invented version/body; decline sends a required trimmed reason≤1000. Parsed returned states determine waiting-payment, rejection or center-handover messaging. A request is not a scheduled visit until backend payment/assignment rules permit it. Deadline/conflict5116 and unknown writes require explicit reconciliation; absence from the pending list is not proof of a specific decision. Decline text remains until explicit dismissal. No caregiver-forbidden booking/patient-detail read is used.

Customer-absence reporting posts /booking-occurrences/{id}/no-show-reports with10–1000 characters, only inside the actual configured check-in window. Pending absence waits for the center; mobile exposes no manager decision. Acknowledge is offered only before start. Home now presents a compact care banner, server-backed Today/Completed counts and the paginated daily visit list without filtering out a separate focus card. It uses the Vietnam day for both from/to; completed counts come from the backend totalElements, never a visible-page sum. The response-needed request card and its count request have been removed from Home; the request inbox remains accessible from Assigned visits. Only a successful zero-total response shows the empty state with Register and Upcoming actions. Register selects Work schedule → Register; View all/Upcoming pass and consume typed list-range parameters so prior filters/history do not override the chosen destination. Loading/read errors remain distinct from an empty day.

The earnings feature is a read-only retained-deposit ledger: GET /deposit-forfeitures and /summary with required from/to Instants. Vietnam-calendar month/year starts are converted to Instants; filtering is by inclusive recorded-at time, not care time. Summary caregiverAmount comes from the backend, never a sum of the visible page, salary estimate or withdrawal balance.

Report lookup scans all booking pages for sessionId. The editor matches FE with two text areas: summary (required, max 4000) and recommendations (optional, max 2000). Overall condition remains an explicit required choice because the BE DTO requires it; no clinical default is invented. Existing meal/medication/mobility/mood notes remain in the typed model and update payload, and in submitted report read-only details, so simplifying the editor does not erase previous content. PUT includes optimistic version. A saved draft ID is retained before upload/submit. Submission requires ENDED and explicit confirmation, and SUBMITTED becomes read-only. BE emits REPORT_SUBMITTED to the booking's customer; mobile does not send separate SMS/email or choose recipients outside backend scope. No clinical condition or vital value is preselected. Max five JPEG/PNG/WebP report photos, each <=10 MB; server validates content/scope.

Unknown-result writes/conflicts block repeats until server reconciliation. Forms remain in memory on failure and guard leaving unsaved content. Backend remains final authority for states, rules, time and authorization.

Availability cancellation uses the existing caregiver contract: `PATCH /caregivers/schedules/{id}/status` with `status: CANCELLED`, a trimmed required reason (maximum 500 characters) and the schedule's actual optimistic `version`. Schedule list/write responses are parsed at the profile boundary; no version is invented. The provider screen labels SCHEDULED as an open availability slot without changing Booking's assigned-visit labels. As in FE, cancellation is offered for SCHEDULED slots whose Vietnam-local end time has not passed; BE rechecks ownership, version, state and assigned bookings and rejects booked slots (409/code4415). Successful cancellation also cancels the linked registration in BE and can reopen the work shift; mobile does not perform those secondary writes itself.

Cancellation requires an explicit reason/confirmation modal. Pending writes lock the form, failed inputs stay in memory, closing a dirty modal requires discard confirmation and uncertain/conflicting writes cannot repeat until an explicit fresh read reconciles the selected slot. No automatic write retry, local-success simulation or direct Booking cancellation is used.

Availability also provides a phone week/day agenda combining all required schedule/visit pages with own time-off intervals. Time off uses GET/POST /caregivers/{id}/time-offs and confirmed DELETE /caregivers/{id}/time-offs/{timeOffId}; no version is invented. Whole-day intervals use Vietnam midnight through exclusive midnight after the last day. Duration is positive and≤30 days, optional reason≤500; caregiver cannot override overlaps with assigned visits. Unknown create/delete reconciliation retains the attempted interval, independently of edits to the form.

Work schedule uses one scroll surface per active section. Agenda week ranges and card dates omit the year visually; underlying ISO dates/queries remain unchanged. Visit cards show patient name, address, date/time and actual status plus View details; availability cards have no patient/address and use their domain label without invented data. Notes and explanatory availability text are excluded from these summary cards but retained in details. View details opens the linked availability detail without launching a cancellation form; the explicit Withdraw approved shift entry supplies `cancel: true` to open that form. Embedded Time off retains the existing modal, dirty-form guard and uncertain-write checkpoints; switching sections is locked while its form is open, a write is pending or its outcome needs reconciliation. Day-agenda time-off links select the integrated Time off section.

Profile professional fields/services remain center-managed. Account name/phone use Identity's numeric10–11-digit contract. Passwords follow the backend strength rule and72-byte UTF-8 bound; confirmation is required locally. Successful change clears secure/in-memory session and protected UI immediately because BE revokes all sessions. Signed-in devices use owner-scoped GET /auth/sessions and confirmed DELETE /auth/sessions/{id}; current-session deletion clears the mobile session.

Device rows parse the backend's `ip` and show browser/OS inferred from `userAgent`, relative last activity and the authoritative `isCurrent` badge; unknown agents retain an unknown-device label rather than guessed device names or raw technical identifiers. The current session sorts first and has no row sign-out action. The list initially shows five rows with View all/Show less. Confirmed Sign out all other devices requires exactly one identified current session and sequentially revokes only other IDs from that displayed snapshot, using the existing per-session endpoint (BE has no bulk API). A failure stops the sequence; explicit successful reconciliation is required after partial/unknown outcomes, with no automatic batch replay or fabricated success. A fresh list determines which sessions remain.

Own avatar/certificate actions use Provider media APIs and original document URIs without copied files. Avatar selection chooses the newest valid HTTPS IMAGE by displayOrder, respecting expiry; image upload≤5MB JPEG/PNG/WebP. Certificate metadata uses actual versions and allows equal issue/expiry dates; creating/updating returns to backend PENDING. PDF/JPEG/PNG attachments≤10MB use a checkpointed certificate ID before upload. Uncertain creates cannot be correlated by display name and remain blocked; uncertain uploads require fresh server links and explicit removal/review of the pending selection before another upload. Professional verification controls are never exposed to caregiver.

Profile presentation mirrors the FE's six completeness criteria: server avatar, Identity phone, Provider dateOfBirth/bio, assigned services and at least one non-rejected certificate that has not expired in Vietnam time. This local display metric does not grant verification or registration eligibility. An additional owner-scoped certificate read supplies that criterion; if it fails, the metric is withheld and a retry is shown without hiding the rest of the profile. Provider dateOfBirth/gender are parsed at the repository boundary; missing experience remains missing rather than a fabricated zero. Pending avatar content URIs may preview locally but do not count as a saved photo. Deposits follow assigned services, Security expands to existing password/device routes, language controls are last. The compact four-button bottom bar retains safe-area and font-scale height adjustments.

Report photos may be selected before a draft exists. Pending content URIs/metadata stay in component memory with no copied patient files. The report repository owns Save/Submit's save-draft → checkpoint ID/version → upload batch → checkpoint attachments workflow; Submit then uses the returned report ID after confirmation. Files are validated before any write and again against the saved draft's attachment count. Malformed successful report write responses are uncertain, never a simulated failure safe to replay. Reconciliation preserves local text/selections and adopts the server ID/version. After an uncertain upload, server photos are shown and the uncertain local batch must be explicitly removed before another selection/upload; BE supplies no upload idempotency key or reliable file correlation. No writes are automatically retried. Selection/removal alone makes no API write, and pending selections participate in dirty-form guards.

## Calendar and notification lifecycle

Provider workDate/startTime/endTime remain Vietnam local UTC+07. Booking timestamps remain Instants and format in device timezone; from/to query dates and today's count use the Vietnam calendar. Home/schedule refresh on resume/date changes.

Foreground NotificationFeed polls unread count/latest page every30 seconds, seeds first reads silently and tracks≤200 IDs plus timestamp watermark in memory. Polls serialize; background/disposal invalidates late results. Logout resets the protected subtree/feed. Owner-scoped inbox supports unread filtering, read/unread, selected read-state/deletion, individual deletion and confirmed clear-read. Mutation counts are parsed; unread count is freshly read, never fabricated. Pages clamp after filtered totals shrink. Resolved occurrence links navigate directly; CAREGIVER_REQUEST/BOOKING opens the request inbox; other booking references scan authorized occurrences instead of reading forbidden booking detail. Banner text remains generic.

BE exposes SSE but no FCM registration contract; this implementation provides foreground inbox/badge/banner, not background OS push.

## Native build and configuration

React Native0.88.1, React19.3.0 and Community CLI20.2.0 are locked in package-lock.json. The maintained android/ source follows the matching official CLI template; generated Gradle/CMake build output and local SDK/signing configuration are ignored. Application ID stays vn.careconnect.careconnect_mobile. Keychain, documents picker, Feather static fonts and community geolocation are autolinked. Location requests are foreground-only and bounded to six seconds, with approximate Android permission accepted; denial sends no coordinates. There is no iOS target.

API_URL in ignored .env is a public gateway origin, inlined by Babel; no other environment fields are bundled. Debug defaults to http://10.0.2.2:8080; LDPlayer supports adb reverse and127.0.0.1. Main Android manifest forbids cleartext, with a debug-only HTTP override; the app also enforces HTTPS API origins in release. Production signing/release is not configured and release is not signed using the debug key. scripts/build-android.ps1 assembles the native debug APK directly; it uses Metro8090, with the port also fixed in Gradle to avoid Identity8081. There is no Expo launcher, prebuild or EAS workflow. Restart Metro with reset-cache after changing bundled public environment configuration.

The Android run wrapper reestablishes ADB reverse for the configured loopback gateway port and Metro8090 before invoking the installed React Native CLI. It uses the same public API_URL/.env precedence as Babel, selects the explicit/single ready device and rejects ambiguous/offline targets. Interactive device selection is rejected for loopback origins because selecting a different target after preparation would leave its gateway unmapped; use --device SERIAL. Direct10.0.2.2/LAN/remote origins keep their existing CLI behavior. An open device is required for loopback preparation; no app data is cleared. This repairs the observed03/11/2026 LDPlayer state: only Metro8090 was reversed, host gateway health was200 and device8080 refused connections; adding8080 restored device HTTP200. It changes development connectivity, not authentication or backend ports.
